# 教师校准与智笔产品接入

## 为什么必须校准

AI评分的流畅解释不能证明评分准确。研究综述显示LLM与人类作文评分的一致性具有较大波动（研究间报告的相关/一致性指标常见约0.30—0.80，指标并非同一量）。因此先进行真实教师标注、比较误差和边界偏差，再宣称分数可靠。不是把模型想象的“二审”当独立阅卷。

## 小规模可行校准（建议，不声称已有）

1. 从相近浙江/新高考题源收集经授权的**真实学生作文及完整原题**，覆盖两题型、低中高各档、典型边界作文、创新但合理情节、语法正确但内容空洞、语言精彩却偏题等；起步可每题型30–50篇，越多越好，不把样本数解释为统计保证。
2. **至少两位有经验教师盲评**：同一明确版本的rubric、互不看模型分数，记录各自档次/分数/判分理由；分歧大的样本由协调教师形成复核/锚点，保留原分歧。
3. 用同题型同量规评估模型的 `MAE`（平均绝对误差）、`RMSE`、`exact_match`、`within_1/within_2` 比例、`band_agreement`、`quadratic_weighted_kappa`、分档/题型偏差；对教师自身一致性也进行测算。
4. 采用**按题目或时间留出**的测试集，避免同篇/改写版在校准样本和测试集重复；测试分不同文体/主题/图片OCR条件/高低档。
5. 通过真实误差分布校正系统性偏高/偏低或锚点语义；不要纯粹对分数乘常数导致跨档错位。结合教师意见迭代评分说明、锚文库和模型配置；每次改动记录版本。
6. 部署监控：按月比较教师复评分、量规更新、OCR失误、题型转移与误判；大分歧时展示低置信提示/人工介入，不是假装知道确切分数。

## 可选双评架构与Token成本

**P0** 单次模型完成事实/要点抽取+盲档次+诊断；确定边界时同一模型专门做反证审查，不要“先改再估分”（改写会污染对原稿判断）。

**P1** 当 `abs(distance_to_band_edge)` 小、故事关键矛盾、OCR不可靠或模型与老师历史校准偏差高时，调用**真实独立**第二轮评分员，并记录两个候选评分及合议结果；普通作文不一定需要第二模型调用。用 rubric 摘要+题目事实表+学生文本而不是塞整个英语总库降低Token成本；检索语料只在讲解阶段按问题增量载入。

## 推荐接口与数据形状（拟议，非既有实现声明）

- `assessEssay({essay_id,task_id,genre,rubric_id,source_text,paragraph_openings,student_text,transcript_confidence,teacher_score?})` 返回 schema 合同（见 `../schemas/review.schema.json`）。
- `getRubric({exam_year,exam_region,task_id})`: rubric完整版本和来源，不返回虚构的“现行标准”。
- `searchRelevantCorpus({student_id,diagnostics,topic,limit})`: 只读用户主库或授权缓存，带来源定位/版本。
- `saveReview({student_id,essay_id,assessment})`: 记录原稿、评估证据、rubric_version、模型版本、时间；需要服务端身份鉴权、幂等写入。文档没有权限执行任何数据库写入。
- `addCorpusItems` 仅用户明确触发、去重、回读。

代码对接步骤：先查看项目 `AGENTS.md`、作文入口、OCR、学生身份、LLM请求层、批改/错误入库、教师反馈、数据存储；寻找原有实现并尽量扩展而非创建第二套评分后端。不要暴露Notion/API令牌给前端。对于多人平台必须隔离各自作文与个人语料。

## 验收门槛提案

没有外部教师数据：只能称**参考估分**；输出必须带量规版本、证据缺失、可解释偏差。存在样本后可以设目标，例如：相比上一版 `MAE`、档次一致率和严重误判占比同时改善；正式上线的阈值需根据教师之间的一致性与目标场景共同商定，不声称“必然±1分”。对评分和**错误诊断**分别验收：老师确认的误判类型、过度修改率、错误定位的高精度、练习迁移能力。
